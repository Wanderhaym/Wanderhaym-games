# Wanderhaym Loader Kit

Готовая переносимая загрузочная заставка Wanderhaym: живой кот-кузнец бьёт молотком, огненная полоса показывает реальный прогресс, от удара вылетают искры, при долгой загрузке кот моргает, а финал раскрывает мир через светящуюся лапу.

## Что загружать в другой проект

Загружайте **всю папку `Wanderhaym-Loader-Kit` целиком**. Не выбирайте кадры по одному: анимации нужны все файлы из `assets`.

Основные файлы:

- `wanderhaym-loader.js` — логика заставки и публичный API;
- `wanderhaym-loader.css` — полностью изолированное оформление;
- `assets/` — утверждённые кадры кота, платформы и звук молотка;
- `demo.html` — автономный рабочий пример;
- `AI-INTEGRATION.md` — точное задание для ИИ, который будет внедрять заставку;
- `original-source/` — копия исходников заставки из Wanderhaym Games для сверки;
- `LICENSE` — условия использования кода и дизайна.

## Быстрая проверка

Откройте папку через любой локальный HTTP-сервер. Например:

```powershell
npx serve .
```

Затем откройте `demo.html`. Напрямую через `file://` ES-модуль может быть заблокирован браузером, поэтому нужен локальный сервер.

## Минимальное подключение

Скопируйте в игру:

```text
wanderhaym-loader/
  wanderhaym-loader.css
  wanderhaym-loader.js
  assets/
```

В HTML подключите стиль:

```html
<link rel="stylesheet" href="./wanderhaym-loader/wanderhaym-loader.css">
```

В стартовом модуле игры:

```js
import { WanderhaymForgeLoader } from './wanderhaym-loader/wanderhaym-loader.js';

const forgeLoader = new WanderhaymForgeLoader();

// Передавайте реальный прогресс от 0 до 1.
forgeLoader.setProgress(0.25);
forgeLoader.setProgress(0.60);
forgeLoader.setProgress(0.92);

// Когда игра действительно готова:
await forgeLoader.complete();
```

Если загрузка завершилась с ошибкой:

```js
forgeLoader.fail('КУЗНЯ ОСТАНОВЛЕНА', 'Обновите страницу и попробуйте снова');
```

## API

### `new WanderhaymForgeLoader(options?)`

Опции:

```js
const forgeLoader = new WanderhaymForgeLoader({
  mount: document.body,
  title: 'Wanderhaym',
  presentText: 'представляет',
  accent: '#ff6b18',
  soundVolume: 0.075,
  assetBase: './wanderhaym-loader/assets/',
  slowConnectionDelay: 6500,
  stallTimeout: 30000,
  completionAssetGrace: 1800,
  onComplete: () => console.log('Мир открыт'),
});
```

`assetBase` обычно указывать не нужно: по умолчанию модуль ищет `assets` рядом с собой.

- `slowConnectionDelay` — через сколько миллисекунд без нового прогресса показать нейтральный статус `ЗАГРУЗКА ЗАНИМАЕТ БОЛЬШЕ ВРЕМЕНИ`; `0` отключает статус. Само время ожидания не считается доказательством плохой сети.
- `stallTimeout` — сколько ждать без нового прогресса перед предупреждением с кнопкой повтора; `0` отключает watchdog. Это не ошибка игры: поздний прогресс или `complete()` автоматически снимают предупреждение.
- `completionAssetGrace` — сколько максимально ждать кадры удара после готовности игры. Затем игра откроется коротким безопасным переходом без невидимого удара.

### `setProgress(value)`

Принимает число от `0` до `1`. Полоса следует реальным данным и не уменьшается назад. До явного `complete()` отображается не более `99%`: `setProgress(1)` не закрывает заставку. Первый фирменный удар при нулевом прогрессе больше не рисует фиктивные `8%`.

### `ready()`

Возвращает `Promise`, который завершается после загрузки и проверки всех кадров. При `404`, повреждённом WebP или изображении без декодируемых пикселей Promise отклоняется. Блокировать загрузку самой игры через `ready()` не требуется: заставка самостоятельно использует поэтапную готовность кадров.

Если заставка завершена или уничтожена до загрузки всех необязательных кадров, незавершённый `ready()` отклоняется с `AbortError`. Это штатная отмена, а не повреждение ассета.

### `complete()`

Доводит полосу до `100%`, запускает финальную ковку, огненную лапу и исчезновение заставки. Текущий удар может сразу стать финальным, поэтому готовая игра не ждёт лишние циклы. Если критические кадры ещё не пришли, после `completionAssetGrace` выполняется безопасный короткий выход. Возвращает `Promise`.

Повторные вызовы возвращают один и тот же Promise. При явном `fail()` незавершённый `complete()` отклоняется с ошибкой; при `destroy()` до конца перехода — с `AbortError`. Предупреждение watchdog не отклоняет Promise и не блокирует позднюю готовность приложения.

### `fail(title, message)`

Останавливает анимацию, показывает ошибку и кнопку `ПОВТОРИТЬ`.

### `destroy()`

Удаляет заставку, отменяет подготовку кадров и очищает ресурсы. После успешного `complete()` ресурсы уже освобождены автоматически: таймеры и обработчики сняты, источники изображений и аудио удалены, карты кадров очищены, пустой корневой элемент скрыт. Браузер самостоятельно решает, когда фактически освободить свой кеш.

## Важные правила бренда

- Не заменять утверждённые кадры кота другими изображениями.
- Не растягивать отдельные кадры разными способами: у всех кадров должен быть один CSS-размер.
- Не убирать первый удар — он начинается даже при нулевом реальном прогрессе, но только после визуальной готовности всех кадров удара.
- При долгой загрузке сохранить моргание кота.
- Финальный переход должен завершаться раскрытием светящейся лапы.
- Надпись оставлять: `Wanderhaym представляет`.
- Не добавлять обратно букву `W` или контур-сигил на заставку.
- Не подключать полный CSS основного сайта вместо `wanderhaym-loader.css`.

## Размер комплекта

Основной вес создают оптимизированные WebP-кадры. Они уже используются действующим сайтом. В комплекте нет Three.js, React, VK Bridge или других библиотек — заставка работает на чистом JavaScript и CSS.

## Как версия 1.0.2 ведёт себя на слабой сети

1. Сначала с высоким приоритетом загружаются только статичный кот и платформа.
2. После их декодирования настоящий утверждённый постер плавно появляется на сцене.
3. Затем загружаются семь кадров удара; одновременно готовятся не более двух кадров.
4. Первый удар ждёт полной готовности кадров, 320 мс проявления постера и 180 мс спокойной позы. Звук пропускается, если аудио не готово.
5. Два кадра моргания начинают загружаться только после завершения первого цикла удара. Повторные удары отмечают продвижение минимум на 16 процентных пунктов, с интервалом начала не менее 1,5 секунды. Финальный удар не ждёт этот интервал.
6. При долгой загрузке появляется нейтральное сообщение; `НЕТ СОЕДИНЕНИЯ` показывается, только если браузер сообщает offline.
7. При полном отсутствии прогресса watchdog показывает предупреждение и кнопку повтора. Загрузка продолжается и может восстановиться.
8. Если игра уже готова, но медиа заставки задерживаются или повреждены, заставка не блокирует вход бесконечно.

## Регрессионная проверка

Запустите `node tests/serve.mjs` и откройте `http://127.0.0.1:4182/tests/index.html`. Страница автоматически проверяет 14 сценариев: явную готовность приложения, восстановление watchdog, медленные/отсутствующие/повреждённые кадры, отмену, очистку, ритм и ветку reduced motion. Сервер слушает только локальный адрес. `tests/` не требуется копировать в игру.
